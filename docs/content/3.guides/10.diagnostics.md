title: Setup diagnostics

Module setup and schema generation diagnostics use stable `NUXT_AUTH_*` codes. Include the code and message when reporting a problem. Each diagnostic carries a suggested fix; most also link to the relevant setup documentation.

These codes describe module configuration and build failures. Sign-in errors retain Better Auth's error codes, and session authorization failures retain their HTTP 401 or 403 status.

| Code | What to check |
| --- | --- |
| `NUXT_AUTH_MISSING_CONFIG` | Create the named config file with a default `defineServerAuth(...)` or `defineClientAuth(...)` export, as directed by the fix. |
| `NUXT_AUTH_NO_DATABASE_PROVIDER` | Ensure the `better-auth:database:providers` hook leaves at least one enabled provider registered. See [custom databases](/guides/custom-database). |
| `NUXT_AUTH_MISSING_HUB_DB` | Load `@nuxthub/core` before this module and configure `hub.db`. See [NuxtHub setup](/integrations/nuxthub). |
| `NUXT_AUTH_INVALID_PLUGIN_SOURCE` | Register an absolute plugin path. Resolve it with `createResolver(import.meta.url).resolve(...)` in the module that registers it. |
| `NUXT_AUTH_STORAGE_CLIENT_ONLY` | Remove `auth.hubSecondaryStorage` or disable `clientOnly`. See [external auth backends](/guides/external-auth-backend). |
| `NUXT_AUTH_SCHEMA_STORAGE_REQUIRED` | With `auth.hubSecondaryStorage: 'custom'`, provide an atomic `secondaryStorage` in `defineServerAuth()`. Otherwise, set the option to `false` to retain database-backed sessions. |
| `NUXT_AUTH_UNSUPPORTED_DIALECT` | Set the NuxtHub database dialect to `sqlite`, `postgresql`, or `mysql`. |
| `NUXT_AUTH_INVALID_CONFIG_EXPORT` | Export `defineServerAuth(...)` as the default export of the named server config file. |
| `NUXT_AUTH_CONFIG_LOAD_FAILED` | Check the underlying error in the message, config imports, and required environment variables. |
| `NUXT_AUTH_EMPTY_SCHEMA` | Check the Better Auth plugins and database options. The schema generator returned no code. |
| `NUXT_AUTH_SCHEMA_GENERATION_FAILED` | Check the underlying error, auth configuration, and write access to the Nuxt build directory. |

In development, an auth config that cannot load produces one error report. The module skips regeneration and leaves an existing generated schema unchanged. Production builds fail on the same config error. Other schema generation failures stop setup in both modes.

After correcting a schema problem, restart Nuxt and check the generated schema before creating a database migration. See [schema generation](/getting-started/schema-generation).
